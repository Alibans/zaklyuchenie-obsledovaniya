# Заключение по обследованию

Задача: по расшифровкам встреч (демонстрация продукта на данных клиента, интервью) собрать документ для клиента. Документ отвечает на три вопроса по каждой функции: **как клиент делает это сейчас → как это делается в 1С → есть ли разрыв и что с ним делаем.**

Документ строится **по бизнес-процессам клиента**, его словами («выставить квитанции», «принять оплату через банк»). Названия документов и справочников 1С — только пояснение в колонке «Как в 1С», никогда не строка реестра.

Подробности:
- [references/struktura.md](references/struktura.md) — структура отчёта, колонки, заключения, приоритеты;
- [references/primery.md](references/primery.md) — примеры строк, хорошие и плохие;
- [references/chek-list.md](references/chek-list.md) — проверка перед выдачей;
- [references/rasshifrovka.md](references/rasshifrovka.md) — если есть только видео/аудио.

## Главные правила

1. **Только то, что есть в записях и материалах.** Не придумывать функции, которые не обсуждали, и не додумывать, что «1С наверняка умеет». Не показали — значит «не показывали», и это вопрос.
2. **Молчание клиента — не согласие.** Согласие — когда клиент сказал «да, так подходит», «удобно», «так и будем». Нет явной реакции → заключение «уточнить».
3. **Каждый вывод — со ссылкой на источник** во внутренних файлах: встреча + таймкод (или примерное место) + короткая цитата. В документ клиенту таймкоды не идут.
4. **Факт и вывод раздельно.** «Клиент сказал…» — факт. «Рекомендуем…» — вывод консультанта, помечается как рекомендация.
5. **Сохранять по ходу.** После каждого шага и каждой обработанной встречи — запись в `Результат\`. Работа может прерваться в любой момент; продолжение — с того, что уже записано.
6. **Пользователь был на встрече, ты — нет.** Спорное не решать молча — выносить в вопросы.

## Порядок работы

### Шаг 0. Проверить входы и продолжение
Все пути ниже — от папки комплекта (где лежат `README.md` и `CLAUDE.md`). Если чат открыт в другой папке — используй полные пути.
- `Входные данные\` пустая — спроси, где лежат расшифровки и материалы, и скопируй их туда (оригиналы не трогать).
- Есть ли файлы в `Результат\`? Есть — прочитай их, скажи пользователю, на каком шаге остановились, и продолжай оттуда.
- Что лежит в `Входные данные\`: расшифровки (`.txt .vtt .srt .md .docx`), `О проекте.md`, требования, КП.
- `.docx` читать так: `powershell -ExecutionPolicy Bypass -File "<папка комплекта>\tools\docx-to-text.ps1" "<файл>"` → рядом в `Результат\_тексты\` появится `.txt`.
- Нет расшифровок, только видео/аудио → [references/rasshifrovka.md](references/rasshifrovka.md).
- Нет `О проекте.md` или в нём пусто — задай пользователю коротко 3–5 вопросов: клиент, продукт, старая программа, участники, кому отдаём. Ответы запиши в `Входные данные\О проекте.md`.

### Шаг 1. Опись встреч → `Результат\01 Опись встреч.md`
По каждой встрече: дата, длительность, участники (по ролям), какие участки показывали — список тем с таймкодами начала. Это оглавление для следующих шагов.

### Шаг 2. Выписки → `Результат\02 Выписки\<дата встречи>.md`
Одна встреча — один файл; длинную расшифровку читать частями. Для каждой обсуждённой функции — запись:

```
### <Функция словами клиента>
- Участок: <контур/процесс>
- Как сейчас: <как делают в старой программе / вручную; кто делает>
- Как показали в 1С: <что и как показали; объекты 1С — в скобках>
- Реакция клиента: согласие / возражение / требование / вопрос / нет реакции
- Цитата: «…» (<таймкод>, <кто сказал>)
- Пожелание клиента: <если звучало>
```
Сюда же — требования, которые клиент назвал сам, вне демонстрации; и функции старой программы, которые упомянули, но не показали в 1С.

### Шаг 3. Реестр функций → `Результат\03 Реестр функций.md`
- Свести выписки всех встреч: одна функция — одна строка; если обсуждали на разных встречах — объединить, взять последнюю договорённость, указать оба источника.
- Сгруппировать: **Участок (контур) → Процесс → Функция**, нумерация 1 → 1.1 → 1.1.1.
- Сверить с требованиями клиента и КП, если они есть: каждое требование должно найтись в реестре; не нашлось — строка «не показывали».
- Поставить заключение и приоритет по правилам из [references/struktura.md](references/struktura.md).
- В конце — сводка: сколько функций по каждому заключению.

### Шаг 4. Вопросы → `Результат\04 Вопросы.md` — и СТОП
Список: «уточнить», «не показывали», спорные трактовки, приоритеты под вопросом. Каждый вопрос — со ссылкой на строку реестра и вариантами ответа, если они понятны.

Остановись и скажи пользователю: «Проверьте `03 Реестр функций.md` и ответьте на вопросы в `04 Вопросы.md` — можно прямо здесь, в чате. Потом напишите „Собирай документ“». Дальше без ответа не идти.

### Шаг 5. Черновик → `Результат\05 Черновик заключения.md`
Учесть ответы пользователя (поправить реестр, снять вопросы). Написать документ по структуре из [references/struktura.md](references/struktura.md). Язык — деловой и простой (раздел «Язык» там же).

### Шаг 6. Документ Word
1. Сделать `Результат\Заключение.html` по шаблону `templates\zaklyuchenie.html` (стили не менять, только содержимое).
2. Собрать: `powershell -ExecutionPolicy Bypass -File "<папка комплекта>\tools\build-docx.ps1" "<папка комплекта>\Результат\Заключение.html" "<папка комплекта>\Результат\Заключение <Клиент> <ГГГГ-ММ-ДД>.docx"`.
3. Нет Word — скрипт скажет; тогда отдать .html и сказать пользователю открыть его в Word и «Сохранить как .docx».
4. Пройти [references/chek-list.md](references/chek-list.md). Сказать пользователю путь к файлу и что проверить глазами.

Правки после сборки — править `05 Черновик…` и `Заключение.html`, собирать заново.
